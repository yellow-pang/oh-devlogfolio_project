## 2. 핵심 기술 선택 이유

### 2.1 Next.js App Router

**선택 이유:**

- `output: "export"` 정적 내보내기 지원 → Firebase Hosting 배포 가능
- 파일 기반 라우팅으로 페이지 구조가 직관적
- `generateStaticParams` + `generateMetadata`로 SEO 메타데이터 제어 가능
- React Server Components 기반으로 클라이언트/서버 컴포넌트 명확히 분리
- 현재 프론트엔드 취업 시장에서 가장 많이 요구되는 스택

**API Routes / Server Actions 미사용 이유:**

- Firebase Hosting은 정적 파일 서빙만 지원 → 서버 사이드 코드 실행 불가
- Firestore client SDK로 모든 CRUD를 브라우저에서 직접 처리
- 서버가 없으므로 배포 비용 없음 (Firebase Hosting 무료 티어 사용)

### 2.2 TypeScript

**선택 이유:**

- 컴파일 시점 타입 오류 방지 → 런타임 버그 사전 차단
- `Post`, `Project` 인터페이스 정의로 데이터 구조 명확화
- `PostFormData`, `ProjectFormData` 타입으로 폼-서비스 레이어 계약 명확화
- 포트폴리오에서 TypeScript 활용 능력 시연

### 2.3 Tailwind CSS + shadcn/ui

**선택 이유:**

| 기준              | Tailwind + shadcn | CSS Modules | styled-components |
| ----------------- | ----------------- | ----------- | ----------------- |
| 개발 속도         | ⭐⭐⭐ 빠름       | ⭐⭐ 보통   | ⭐⭐ 보통         |
| 다크 모드 지원    | ⭐⭐⭐ 내장       | ⭐⭐ 수동   | ⭐⭐ 수동         |
| 커스터마이징      | ⭐⭐⭐ 높음       | ⭐⭐⭐ 높음 | ⭐⭐ 보통         |
| 포트폴리오 가시성 | ⭐⭐⭐ 높음       | ⭐⭐ 보통   | ⭐⭐ 보통         |

- shadcn/ui는 복사-붙여넣기 방식으로 컴포넌트를 직접 소유 → 커스터마이징 자유도 높음
- `Button`, `Card`, `Badge`, `Input`, `Dialog` 등 Admin 대시보드 UI를 빠르게 구성
- Tailwind v4 채택으로 최신 CSS 변수 기반 테마 시스템 활용

### 2.4 Firebase (Firestore + Hosting)

**선택 이유:**

- **무료 티어**: 개인 포트폴리오/블로그 트래픽 수준에서 비용 없음
- **Hosting**: 정적 파일 CDN 배포, 커스텀 도메인 지원, SSL 자동
- **Firestore**: NoSQL 문서 DB, client SDK로 직접 읽기/쓰기 가능
- **Auth**: Email/Password 인증 (Admin 보호용, 2차 구현)
- 한 플랫폼에서 배포 + DB + 인증을 해결 → 운영 복잡도 최소화

**백엔드 서버를 만들지 않은 이유:**

- 개인 포트폴리오/블로그는 관리자(본인)만 쓰기 작업 → 복잡한 서버 불필요
- Firestore 보안 규칙으로 읽기/쓰기 권한 제어 가능
- 서버 유지보수 부담 없음

### 2.5 framer-motion

**선택 이유:**

- 포트폴리오 특성상 첫 인상이 중요 → 진입 애니메이션으로 생동감 추가
- `whileInView` API로 스크롤 트리거 애니메이션 간단 구현
- 과한 애니메이션 없이 `opacity + y` 기본 트랜지션만 사용 → 성능 영향 최소화

### 2.6 react-markdown + rehype-highlight

**선택 이유:**

- 블로그 본문을 Markdown으로 작성 → 별도 에디터 없이 텍스트로 관리 가능
- `rehype-highlight`로 코드 블록 신택스 하이라이팅 자동 적용
- `remark-gfm`으로 테이블, 체크리스트 등 GitHub Markdown 확장 지원

### 2.7 react-hook-form

**선택 이유:**

- Admin 폼에서 유효성 검사와 제출 처리를 선언적으로 관리
- 비제어 컴포넌트 기반 → 렌더링 최적화
- `register`, `handleSubmit`, `formState` API로 보일러플레이트 최소화

## 3. 아키텍처 구조

### 3.1 전체 구조 (정적 클라이언트 사이드)

```
                   Firebase Hosting
                   (정적 파일 CDN)
                         │
                    out/ (빌드 결과)
                         │
                   Next.js App Router
                   (정적 내보내기)
                         │
        ┌────────────────┼────────────────┐
        │                │                │
   Page 컴포넌트    UI 컴포넌트       Custom Hooks
  (app/ 폴더)   (components/)    (hooks/)
        │                │                │
        └────────────────┴───────────────-┘
                         │
                   서비스 레이어
                 (lib/services/)
                         │
              ┌──────────┴──────────┐
              │                     │
         mock 데이터            Cloud Firestore
       (lib/mock/)            (firebase/config.ts)
       [현재 사용 중]           [7단계에서 교체]
```

### 3.2 레이어 책임 분리

| 레이어            | 위치                  | 역할                                            |
| ----------------- | --------------------- | ----------------------------------------------- |
| **Page**          | `src/app/**`          | 라우팅, 데이터 요청, 레이아웃 조합              |
| **UI 컴포넌트**   | `src/components/**`   | 재사용 가능한 표현 컴포넌트                     |
| **Custom Hook**   | `src/hooks/**`        | Admin 페이지의 CRUD 상태 관리                   |
| **서비스 레이어** | `src/lib/services/**` | 데이터 접근 추상화 (mock ↔ Firestore 교체 지점) |
| **타입 정의**     | `src/types/**`        | Post, Project 인터페이스                        |
| **설정**          | `src/config/site.ts`  | 사이트 메타데이터 중앙 관리                     |

### 3.3 컴포넌트 분류

```
components/
  admin/          ← 관리자 전용 컴포넌트 (CRUD 폼, 사이드바)
  blog/           ← 블로그 전용 컴포넌트 (포스트 카드, Markdown 렌더러)
  common/         ← 공통 컴포넌트 (PageHeader, TagBadge, ThemeToggle)
  layout/         ← 레이아웃 컴포넌트 (Header, Footer)
  portfolio/      ← 포트폴리오 전용 컴포넌트 (Hero, Skills, Projects, Contact)
  providers/      ← Context Provider (ThemeProvider)
  ui/             ← shadcn/ui 기본 컴포넌트
```

## 4. 결정하지 않은 것 (의도적 제외)

| 결정                                  | 이유                                             |
| ------------------------------------- | ------------------------------------------------ |
| 상태 관리 라이브러리 (Zustand, Redux) | 페이지 간 공유 상태가 없음. Custom Hook으로 충분 |
| API Routes                            | Firebase Hosting 정적 배포와 호환 안 됨          |
| ORM / 쿼리 빌더                       | Firestore는 자체 SDK 사용                        |
| 서버 사이드 렌더링 (SSR)              | Firebase Hosting은 정적 파일만 지원              |
| 테스트 (Jest, Cypress)                | MVP 우선 구현 후 추가 검토                       |
| 댓글 시스템                           | 독자 기반 형성 후 Giscus 연동 검토               |
