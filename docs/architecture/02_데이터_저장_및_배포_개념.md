# 데이터 저장 및 배포 개념

> "배포해도 수정한 내용이 사라지지 않는 이유"

---

## 1. 핵심 개념: 코드와 데이터는 별개다

이 프로젝트는 두 가지가 완전히 분리되어 있습니다.

| 구분                                   | 저장 위치                        | 배포 시 영향                   |
| -------------------------------------- | -------------------------------- | ------------------------------ |
| **코드** (화면 구조, 디자인, 기능)     | GitHub → Firebase Hosting        | 배포할 때마다 새 코드로 교체됨 |
| **데이터** (글, 프로젝트, 사이트 설정) | Firebase Firestore (클라우드 DB) | 배포와 완전히 무관, 유지됨     |

배포는 **코드만** 교체합니다. Firestore에 저장된 데이터는 건드리지 않습니다.

---

## 2. 정적 빌드(Static Export)란?

이 프로젝트는 `next.config.ts`에 `output: "export"`가 설정되어 있습니다.

```ts
const nextConfig = {
  output: "export", // 정적 파일로 빌드
};
```

### 빌드 결과물

`npm run build`를 실행하면 `out/` 폴더에 순수한 HTML/CSS/JS 파일이 생성됩니다.

```
out/
├── index.html       ← 홈 페이지
├── blog.html        ← 블로그 페이지
├── admin/
│   ├── index.html   ← 관리자 대시보드
│   ├── login.html
│   └── settings.html
└── _next/
    └── static/      ← JS, CSS 번들
```

이 파일들은 **빌드 시점의 코드**로만 구성됩니다. 데이터는 포함되지 않습니다.

### Firebase Hosting의 역할

Firebase Hosting은 이 `out/` 폴더를 그대로 CDN에 올려서 전 세계에 배포합니다.  
즉 Firebase Hosting은 **파일 서버**일 뿐, 데이터베이스와는 무관합니다.

---

## 3. Firestore는 어디에 있나?

Firestore는 Google의 클라우드 데이터베이스 서비스입니다.  
Firebase Hosting과는 **별개의 독립적인 서비스**입니다.

```
사용자 브라우저
    │
    ├── HTML/CSS/JS 요청 ──────→ Firebase Hosting (파일 서버)
    │                              out/ 폴더의 파일을 응답
    │
    └── 데이터 요청 ────────────→ Firebase Firestore (클라우드 DB)
                                   posts, projects, siteSettings 컬렉션
```

브라우저가 페이지를 열면:

1. Firebase Hosting에서 HTML/JS 파일을 받아옴
2. JS가 실행되면서 Firestore에 직접 데이터를 요청
3. Firestore가 데이터를 응답 → 화면에 표시

---

## 4. 사이트 설정이 유지되는 이유

`/admin/settings`에서 저장 버튼을 누르면:

```
저장 버튼 클릭
    └→ saveSiteSettings() 호출
         └→ Firestore의 siteSettings/main 도큐먼트에 저장
              └→ 클라우드 DB에 영구 보관
```

이후 배포를 다시 해도:

```
npm run build → firebase deploy
    └→ out/ 폴더(코드)만 교체
         └→ Firestore 데이터는 전혀 건드리지 않음 ✅
```

홈 페이지를 열면:

```
페이지 로드
    └→ getSiteSettings() 호출
         └→ Firestore에서 siteSettings/main 읽어옴
              └→ 저장해둔 값 그대로 표시
```

## 5. 그렇다면 언제 데이터가 사라지나?

| 상황                                   | 데이터 유지 여부                  |
| -------------------------------------- | --------------------------------- |
| 코드 수정 후 재배포                    | ✅ 유지                           |
| 브라우저 새로고침                      | ✅ 유지                           |
| 다른 기기에서 접속                     | ✅ 유지 (클라우드이므로)          |
| Firebase 프로젝트 삭제                 | ❌ 사라짐                         |
| Firestore에서 직접 도큐먼트 삭제       | ❌ 사라짐                         |
| `defaultSiteSettings` 폴백 코드가 실행 | — Firestore 데이터 없을 때만 적용 |

---

## 6. localhost에서도 같은 Firestore를 쓰는 이유

`localhost`와 배포 사이트 모두 `.env.local`에 설정된 **동일한 Firebase 프로젝트**에 연결됩니다.

```
NEXT_PUBLIC_FIREBASE_PROJECT_ID=oh-devlogfolio  ← 동일한 프로젝트
```

따라서:

- `localhost`에서 저장 → 배포 사이트에서도 반영
- 배포 사이트에서 저장 → `localhost`에서도 반영

개발 환경과 프로덕션이 같은 DB를 공유하는 구조입니다.  
(규모가 커지면 개발용 Firebase 에뮬레이터나 별도 프로젝트를 분리하기도 합니다.)

---

## 7. 전체 흐름 요약

```
[개발자]
    │
    ├── 코드 수정 → git push → PR → 머지
    │       └→ npm run build → firebase deploy
    │                └→ Firebase Hosting 업데이트 (코드만)
    │
    └── Admin 패널에서 데이터 수정
            └→ Firestore 업데이트 (데이터만)

[사용자가 사이트 접속]
    └→ Hosting에서 코드(JS) 받음
         └→ JS가 Firestore에서 데이터 받음
              └→ 화면 렌더링
```
