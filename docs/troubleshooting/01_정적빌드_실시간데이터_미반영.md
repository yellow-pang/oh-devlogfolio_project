# 정적 빌드 환경에서 콘텐츠 실시간 반영 문제

> 작성일: 2026-05-28

---

## 1. 문제 발생

### 증상 1 — 콘텐츠 미반영

관리자 페이지(`/admin`)에서 프로젝트 또는 블로그 포스트를 등록·수정해도  
화면(`/`, `/projects`, `/blog`, `/blog/[slug]`)에 변경 내용이 전혀 반영되지 않음.  
Firestore Console에서는 데이터가 정상적으로 저장된 것을 확인했으나 UI는 그대로였음.

### 증상 2 — 빌드 오류

클라이언트 컴포넌트 전환 과정에서 아래 오류 발생:

```
Error: Page "/blog/[slug]" is missing "generateStaticParams()" so it cannot be used with "output: export" config.
```

---

## 2. 원인 파악

### 원인 A — `output: "export"` + Server Component 조합

`next.config.ts`에 `output: "export"` 설정이 적용되어 있어 `next build` 실행 시  
모든 페이지가 **정적 HTML 파일로 변환**된다.

```ts
// next.config.ts
const nextConfig: NextConfig = {
  output: "export", // ← 빌드 시 정적 HTML 생성
  images: { unoptimized: true },
};
```

문제가 된 네 페이지는 모두 **async Server Component**로 작성되어 있었다.

```tsx
// 예시 — app/projects/page.tsx (문제 코드)
export default async function ProjectsPage() {
  const projects = await getAllProjects(); // 빌드 타임에 1회만 실행
  ...
}
```

| 단계                        | 동작                                                |
| --------------------------- | --------------------------------------------------- |
| `next build` 실행           | Firestore에서 데이터를 가져와 HTML로 고정           |
| 관리자에서 데이터 등록/수정 | Firestore에는 저장되나 이미 생성된 HTML은 변경 없음 |
| 사용자가 페이지 접근        | 빌드 시점의 구 데이터만 표시됨                      |

### 원인 B — `"use client"` + `generateStaticParams` 충돌

`/blog/[slug]` 페이지를 `"use client"`로 전환하는 과정에서  
`generateStaticParams()`를 함께 제거하자,  
`output: "export"` 설정이 동적 라우트에 반드시 `generateStaticParams`를 요구하여 빌드 실패.

## 3. 해결 방법 후보

### 방법 1 — ISR (Incremental Static Regeneration)

`revalidate` 옵션으로 주기적으로 페이지를 재생성.

- **장점**: SEO 최적화, 초기 로딩 속도 빠름
- **단점**: Firebase Hosting은 서버리스 런타임을 지원하지 않아 **ISR 사용 불가**

### 방법 2 — 클라이언트 컴포넌트 전환 (`"use client"` + `useEffect`)

페이지를 Client Component로 전환해 브라우저 런타임에 직접 Firestore를 호출.

- **장점**: 재빌드 없이 항상 최신 데이터 반영, Firebase Hosting 제약 없음
- **단점**: 초기 렌더링 시 로딩 상태 발생, SEO 메타 정보 별도 처리 필요

### 방법 3 — 빌드 자동화 (CI/CD 재빌드 트리거)

데이터 변경 시마다 자동으로 재빌드·재배포.

- **장점**: 기존 아키텍처 유지 가능
- **단점**: Cloud Functions 또는 외부 CI 서버 필요 — 현재 프로젝트 제약(Cloud Functions 미사용)에 위배

---

## 4. 선택한 해결 방식 및 이유

**방법 2 — 클라이언트 컴포넌트 전환**을 선택.

| 판단 기준             | 이유                                                                          |
| --------------------- | ----------------------------------------------------------------------------- |
| Firebase Hosting 호환 | 서버 런타임 없이 동작 → ISR 불가, CI 트리거는 제약 위배                       |
| 프로젝트 제약 준수    | Cloud Functions 미사용, API Routes 미사용 조건 충족                           |
| 실시간성              | 관리자 수정 후 새로고침만으로 즉시 반영                                       |
| 구현 단순성           | 기존 서비스 함수(`getAllProjects`, `getPublishedPosts` 등) 그대로 재사용 가능 |

`/blog/[slug]` 페이지의 빌드 오류(원인 B)는 다음 구조로 해결:

- **`page.tsx`**: Server Component로 유지 → `generateStaticParams` export (빌드 오류 해소)
- **`BlogPostClient.tsx`**: Client Component로 분리 → 런타임 Firestore fetch

또한 빌드 이후 새로 추가된 포스트의 slug URL을 처리하기 위해  
`firebase.json`에 SPA rewrite 규칙을 추가했다.

## 5. 적용 내용

### 5-1. `app/page.tsx` — 홈 화면

```tsx
"use client";

export default function HomePage() {
  const [projects, setProjects] = useState<Project[]>([]);
  const [recentPosts, setRecentPosts] = useState<Post[]>([]);

  useEffect(() => {
    getAllProjects().then(setProjects);
    getPublishedPosts().then((posts) => setRecentPosts(posts.slice(0, 3)));
  }, []);
  ...
}
```

### 5-2. `app/projects/page.tsx` — 프로젝트 목록

```tsx
"use client";

export default function ProjectsPage() {
  const [projects, setProjects] = useState<Project[]>([]);
```

### 5-4. `app/blog/[slug]/page.tsx` + `BlogPostClient.tsx` — 포스트 상세

**`page.tsx`** (서버 컴포넌트 래퍼 — `generateStaticParams` 유지):

```tsx
import { getPublishedPosts } from "@/lib/services/posts";
import BlogPostClient from "./BlogPostClient";

export async function generateStaticParams() {
  const posts = await getPublishedPosts();
  return posts.map((post) => ({ slug: post.slug }));
}

export default async function BlogPostPage({ params }) {
  const { slug } = await params;
  return <BlogPostClient slug={slug} />;
}
```

**`BlogPostClient.tsx`** (클라이언트 컴포넌트 — 런타임 fetch):

```tsx
"use client";

export default function BlogPostClient({ slug }: { slug: string }) {
  const [post, setPost] = useState<Post | null | undefined>(undefined);

  useEffect(() => {
    async function load() {
      const [found, allPosts] = await Promise.all([
        getPostBySlug(slug),
        getPublishedPosts(),
      ]);
      ...
    }
    load();
  }, [slug]);
  ...
}
```

### 5-5. `firebase.json` — SPA rewrite 추가

빌드 이후 새로 등록된 포스트의 slug URL 접근 시 404를 방지:

```json
{
  "hosting": {
    "public": "out",
    "rewrites": [{ "source": "**", "destination": "/index.html" }]
  }
}
```
