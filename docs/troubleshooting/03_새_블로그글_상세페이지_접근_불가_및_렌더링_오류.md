# 새 블로그 글 상세 페이지 접근 불가 및 렌더링 오류

> 작성일: 2026-05-28

---

## 1. 문제 확인

### 1.1. 증상

배포가 완료된 상태에서 관리자 화면(`/admin`)을 통해 **새로운 프로젝트**와 **새로운 블로그 글**을 추가함.

- **프로젝트**: 홈 화면(`/`) 및 프로젝트 목록에 즉시 정상적으로 반영됨.
- **블로그 글**: 블로그 목록(`/blog`)에는 데이터가 반영된 것처럼 보이나, 해당 글을 클릭하여 상세 페이지(`/blog/새로운-글-slug`)로 진입하면 화면이 열리지 않거나 UI가 심각하게 깨지는(렌더링이 멈추는) 현상이 발생함.

---

## 2. 원인 분석

왜 '목록형'인 프로젝트는 잘 되고, '상세형'인 블로그만 문제가 생겼는지 두 가지 측면에서 파악됨.

### 2.1. 정적 빌드(`output: "export"`)와 동적 라우팅의 한계

- **프로젝트 (`/projects`)**: 단일 페이지에서 클라이언트 사이드로 Firestore 데이터를 불러와 목록을 렌더링하므로, 새로 추가된 데이터가 즉시 반영됨.
- **블로그 상세 (`/blog/[slug]`)**: Next.js의 정적 빌드 환경에서는 `next build`를 실행하는 시점에 존재했던 데이터만 물리적인 HTML 파일(`post-1.html`)로 생성됨. 빌드 이후에 관리자 화면에서 추가한 새 글은 **해당 URL에 대응하는 HTML 파일이 서버에 존재하지 않으므로** 접근이 불가함.

### 2.2. `firebase.json`의 잘못된 Rewrite 규칙에 따른 Hydration 충돌

HTML 파일이 없으면 정상적인 404 Not Found 에러가 발생해야 하지만, 기존 `firebase.json`에 아래와 같은 설정이 존재했음.

```json
"rewrites": [
  {
    "source": "/blog/**",
    "destination": "/blog.html"
  }
]
```

이 설정으로 인해 새로 추가한 글(`/blog/new-post`)에 접속하면, Firebase는 404 에러를 무시하고 억지로 **블로그 목록 페이지(`/blog.html`)**를 반환함.
결과적으로 브라우저 주소창(상세 페이지)과 실제로 받아온 HTML 뼈대(목록 페이지)가 불일치하여, React의 Hydration 과정에서 심각한 오류가 발생하고 화면이 깨짐.

---

## 3. 수정 방식 비교

이 문제를 해결하기 위해 3가지 접근 방식을 비교함.

### 방법 1: SPA Fallback (`**` → `/index.html` 우회)

- **방식**: 없는 주소로 접근 시 `index.html`을 반환하여 클라이언트 단에서 렌더링을 처리하게 유도.
- **장점**: 관리자에서 새 글을 쓰자마자 즉시 접근 가능.
- **단점**: App Router 환경에서 정적 페이로드(`.txt` 데이터) 누락으로 인한 잦은 404 오류 유발(기존 `02_` 문서 참조), SEO(검색엔진 최적화)에 취약함.

### 방법 2: Query 파라미터 기반 단일 라우팅 (`/blog/post?slug=...`)

- **방식**: `/blog/[slug]` 구조를 버리고, 하나의 고정된 페이지가 쿼리스트링을 읽어 데이터를 불러오도록 변경.
- **장점**: 빌드 없이 즉각적인 실시간 포스트 렌더링 가능.
- **단점**: 깔끔한 URL 구조를 포기해야 하며, 블로그의 핵심인 SEO(검색엔진 노출) 측면에서 매우 큰 손해.

### 방법 3: 정적 블로그 운영 정석 (글 작성 후 수동 재빌드) ⭐️

- **방식**: 잘못된 Rewrite 규칙을 제거하여 없는 글은 404를 반환하게 하고, 새 글 작성 후엔 반드시 `npm run build`와 `firebase deploy`를 수행하여 새로운 HTML을 굽는 방식.
- **장점**: 완벽한 SEO, 깔끔한 URL, 로딩 지연 없는 빠른 속도(SSG 이점 100% 활용).
- **단점**: 새 글을 쓸 때마다 빌드 명령어를 실행해야 하는 번거로움 존재.

---

## 4. 선택하여 수정 후 정상 동작 확인

**[방법 3: 정석적인 재빌드 방식]**을 최종 채택함.
포트폴리오 겸 개발 블로그라는 서비스 목적상 **SEO와 깔끔한 URL 구조**를 유지하는 것이 최우선이기 때문.

### 4.1. 적용 내용

1. `firebase.json`에서 혼란을 주던 `rewrites` 설정을 완전히 삭제하여, 존재하지 않는 페이지는 깔끔하게 404를 내뱉도록 원복함.

```json
// firebase.json 수정 후
{
  "hosting": {
    "public": "out",
    "cleanUrls": true,
    "ignore": ["firebase.json", "**/.*", "**/node_modules/**"]
  }
}
```

2. 운영 프로세스 확립: **"관리자 페이지에서 새 블로그 글을 작성/수정한 직후에는 반드시 재빌드 및 배포를 진행한다."**

### 4.2. 결과 확인

1. 로컬 환경에서 새 블로그 글 작성.
2. `npm run build` 실행 → 터미널에서 새 글의 `generateStaticParams`가 정상 작동하여 새로운 `.html`이 구워지는 것을 확인.
3. `firebase deploy --only hosting` 실행.
4. 배포된 서버에서 새 블로그 글 URL(`/blog/new-post`) 진입 시, 렌더링 깨짐 없이 화면이 **정상적으로 즉시 표출됨**을 확인 완료.
