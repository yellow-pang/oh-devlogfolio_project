## 1. 현재 상태

현재는 **in-memory mock 데이터**를 사용합니다.  
`lib/mock/posts.ts`, `lib/mock/projects.ts`에 정적 배열로 정의되어 있으며,  
`lib/services/posts.ts`, `lib/services/projects.ts`에서 이를 읽고 씁니다.

> **주의:** mock 데이터는 새로고침 시 Admin CRUD 결과가 초기화됩니다.  
> Firestore 연결 후 해결됩니다.

## 2. Firestore 컬렉션 구조

### 2.1 `posts` 컬렉션

**컬렉션 경로:** `posts/{postId}`

| 필드명         | 타입        | 설명                        | 예시                             |
| -------------- | ----------- | --------------------------- | -------------------------------- |
| `id`           | `string`    | Firestore 자동 생성 문서 ID | `"abc123"`                       |
| `title`        | `string`    | 포스트 제목                 | `"Next.js App Router 완전 정복"` |
| `slug`         | `string`    | URL 경로용 슬러그 (고유값)  | `"nextjs-app-router-guide"`      |
| `excerpt`      | `string`    | 목록에 표시되는 요약        | `"App Router의 핵심 개념 정리"`  |
| `content`      | `string`    | Markdown 형식의 본문 전체   | `"# 제목\n\n본문..."`            |
| `thumbnailUrl` | `string`    | 썸네일 이미지 URL 또는 경로 | `"/images/post-1.png"`           |
| `tags`         | `string[]`  | 태그 목록                   | `["Next.js", "React"]`           |
| `published`    | `boolean`   | 공개 여부                   | `true`                           |
| `createdAt`    | `Timestamp` | 작성일 (serverTimestamp)    | `Timestamp`                      |
| `updatedAt`    | `Timestamp` | 수정일 (serverTimestamp)    | `Timestamp`                      |

**TypeScript 인터페이스 (현재):**

```typescript
// src/types/post.ts
export interface Post {
  id: string;
  title: string;
  slug: string;
  excerpt: string;
  content: string;
  thumbnailUrl: string;
  tags: string[];
  published: boolean;
  createdAt: string; // mock: ISO string, Firestore 연결 후 Timestamp → string 변환 필요
  updatedAt: string;
}
```

**향후 추가 검토 필드:**

| 필드명      | 타입     | 설명                                                        |
| ----------- | -------- | ----------------------------------------------------------- |
| `category`  | `string` | 블로그 카테고리 (알고리즘/개발일지/언어&도구/개념정리/회고) |
| `viewCount` | `number` | 조회수 (Firestore 트랜잭션 기반, 2차 구현)                  |

## 4. Firestore 보안 규칙 (계획)

```javascript
// firestore.rules
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // posts 컬렉션
    match /posts/{postId} {
      // 읽기: 공개 포스트는 누구나, 비공개 포스트는 인증된 사용자만
      allow read: if resource.data.published == true
                  || request.auth != null;
      // 쓰기: 인증된 사용자만
      allow write: if request.auth != null;
    }

    // projects 컬렉션
    match /projects/{projectId} {
      // 읽기: 누구나
      allow read: if true;
      // 쓰기: 인증된 사용자만
      allow write: if request.auth != null;
    }
  }
}
```

## 5. Timestamp 처리 전략

Firestore `Timestamp`는 화면 표시 시 문자열로 변환해야 합니다.

```typescript
import { Timestamp } from "firebase/firestore";
import { format } from "date-fns";
import { ko } from "date-fns/locale";

// Firestore Timestamp → 화면 표시용 문자열 변환
function formatTimestamp(ts: Timestamp | string): string {
  const date = ts instanceof Timestamp ? ts.toDate() : new Date(ts);
  return format(date, "PPP", { locale: ko }); // 예: 2026년 5월 27일
}
```

서비스 함수에서 Firestore 문서를 반환할 때 `createdAt`, `updatedAt`을 ISO 문자열로 변환하여 기존 `Post`, `Project` 인터페이스와 호환성을 유지합니다.

```typescript
// Firestore 문서 → Post 객체 변환 예시
function toPost(doc: DocumentSnapshot): Post {
  const data = doc.data()!;
  return {
    ...data,
    id: doc.id,
    createdAt: (data.createdAt as Timestamp).toDate().toISOString(),
    updatedAt: (data.updatedAt as Timestamp).toDate().toISOString(),
  } as Post;
}
```
