# 관리자(Admin) 기능 가이드

> 이 문서는 ohdevlogfolio의 관리자 페이지 전체를 설명합니다.  
> 블로그 글과 프로젝트를 추가·수정·삭제하고, 카테고리를 관리하는 방법을 다룹니다.

---

## 1. 관리자 페이지란?

관리자 페이지는 사이트 소유자(개발자 본인)만 접근해서  
**블로그 글, 프로젝트, 카테고리 데이터를 관리하는 백오피스(관리 도구)** 입니다.

> **백오피스(Back Office)란?**  
> 일반 방문자에게 보이지 않는 내부 관리 화면입니다.  
> 쇼핑몰로 치면 상품을 등록·수정하는 어드민 화면과 같습니다.

---

## 2. 관리자 URL 구조

| URL                 | 페이지        | 기능                           |
| ------------------- | ------------- | ------------------------------ |
| `/admin`            | 대시보드      | 전체 현황 (글 수, 프로젝트 수) |
| `/admin/posts`      | 포스트 관리   | 블로그 글 목록·추가·수정·삭제  |
| `/admin/projects`   | 프로젝트 관리 | 프로젝트 목록·추가·수정·삭제   |
| `/admin/categories` | 카테고리 관리 | 카테고리 추가·수정·삭제        |

## 3. 관리자 레이아웃

모든 Admin 페이지는 공통 레이아웃(`src/app/admin/layout.tsx`)을 사용합니다.  
왼쪽에 사이드바 네비게이션이 있어 각 관리 페이지로 빠르게 이동할 수 있습니다.

```
┌──────────┬────────────────────────────────────┐
│ Admin    │                                    │
│ 사이드바  │       메인 콘텐츠 영역              │
│          │                                    │
│ 📊 대시보드│                                    │
│ 📝 포스트 │                                    │
│ 💼 프로젝트│                                    │
│ 🏷 카테고리│                                    │
└──────────┴────────────────────────────────────┘
```

**관련 파일:**

- `src/app/admin/layout.tsx` — 공통 레이아웃
- `src/components/admin/AdminSidebar.tsx` — 사이드바 컴포넌트
- `src/components/admin/adminNav.ts` — 사이드바 메뉴 항목 정의

## 4. 포스트 관리 (`/admin/posts`)

### 4.1 목록 화면

공개된 글과 비공개 글을 포함한 **전체 블로그 글 목록**을 보여줍니다.  
(일반 `/blog` 페이지는 공개 글만 표시하지만, 여기서는 전부 보입니다.)

```
┌──────────────────────────────────────────────────┐
│  포스트 관리                    [+ 새 포스트]      │
├──────────────────────────────────────────────────┤
│  [검색창 🔍]                                      │
├──────────────────────────────────────────────────┤
│  제목            카테고리  공개 여부  작업         │
│  ──────────────────────────────────────────────  │
│  Next.js 완전정복 개발일지  [공개 ●]  [수정][삭제] │
│  TypeScript 팁   개념정리  [비공개○]  [수정][삭제] │
│  ...                                             │
└──────────────────────────────────────────────────┘
```

### 4.2 검색 기능

목록 상단 검색창에 키워드를 입력하면 **제목 기준으로 즉시 필터링**됩니다.

### 4.3 공개/비공개 빠른 토글

목록의 [공개/비공개] 버튼을 클릭하면, **폼을 열지 않고 즉시** 공개 상태가 전환됩니다.

```
[공개 ●] 클릭
    │
    ▼
togglePublish(post.id, post.published)
    │
    ▼
published: true → false (비공개로 변경)
화면 즉시 반영
```

### 4.4 삭제 확인 (AlertDialog)

[삭제] 버튼을 클릭하면 바로 삭제되지 않고, **확인 다이얼로그**가 열립니다.  
실수로 삭제하는 것을 방지하기 위해서입니다.

```
[삭제] 클릭
    │
    ▼
AlertDialog 열림:
"이 포스트를 삭제하시겠습니까? 이 작업은 되돌릴 수 없습니다."
    │
┌───┴────────────────────┐
│  [취소]               │  [삭제 확인]
│     │                 │       │
│  다이얼로그 닫힘         │  포스트 삭제 실행
└────────────────────────┘
```

## 5. PostForm — 포스트 작성/수정 폼

새 포스트 추가 또는 기존 포스트 수정 시 나타나는 폼입니다.

### 5.1 폼 필드 목록

| 필드           | 입력 형식   | 필수 여부 | 설명                                          |
| -------------- | ----------- | --------- | --------------------------------------------- |
| 제목 (title)   | 텍스트      | ✅ 필수   | 블로그 글 제목                                |
| Slug           | 텍스트      | ✅ 필수   | URL에 사용될 고유 식별자 (예: `my-post-slug`) |
| 썸네일 URL     | 텍스트      | 선택      | 이미지 URL 입력 → **실시간 미리보기**         |
| 요약 (excerpt) | 텍스트 영역 | ✅ 필수   | 목록에서 미리보기로 표시되는 짧은 설명        |
| 본문 (content) | 텍스트 영역 | 선택      | Markdown 형식으로 작성하는 글 본문            |
| 태그           | 텍스트      | 선택      | 쉼표로 구분 (예: `React,TypeScript`)          |
| 카테고리       | 드롭다운    | 선택      | 카테고리 관리 목록에서 선택                   |
| 공개 여부      | 체크박스    | —         | 체크 = 공개, 미체크 = 비공개                  |

### 5.2 썸네일 실시간 미리보기

URL을 입력하는 순간 **폼 안에서 이미지가 바로 표시**됩니다.  
잘못된 URL이면 이미지가 표시되지 않습니다. (에러 처리 포함)

```
[썸네일 URL 입력창]
https://example.com/image.jpg
    │  useWatch로 입력값 실시간 감지
    ▼
┌──────────────────────────────┐
│    [이미지 미리보기 표시]     │
└──────────────────────────────┘
```

> **useWatch란?**  
> `react-hook-form`의 기능으로, 폼의 특정 필드 값을 실시간으로 감시합니다.  
> 값이 변경될 때마다 컴포넌트가 다시 렌더링되어 미리보기를 업데이트합니다.

### 5.3 카테고리 드롭다운

카테고리 필드는 텍스트 입력이 아닌 **드롭다운 Select 메뉴**입니다.  
`useCategories()` 훅을 통해 현재 등록된 카테고리 목록을 불러와 선택지로 제공합니다.

```
카테고리 드롭다운 클릭
    │
    ▼
useCategories() → categories 배열 불러오기
    │
    ▼
[없음]
[개발일지]
[알고리즘]
[언어/도구]
[개념정리]
[회고]
```

### 6.1 목록 화면

```
┌──────────────────────────────────────────────────────┐
│  프로젝트 관리                     [+ 새 프로젝트]    │

├──────────────────────────────────────────────────────┤
│  제목           대표 여부  작업                        │
│  ──────────────────────────────────────────────────  │
│  ohdevlogfolio  [★ 대표]   [수정][삭제]               │
│  algorithm-viz  [☆]        [수정][삭제]               │
└──────────────────────────────────────────────────────┘
```

### 6.2 featured 빠른 토글

[★/☆] 버튼으로 대표 프로젝트 여부를 즉시 전환합니다.

| 상태             | 아이콘 | 색상          | 의미          |
| ---------------- | ------ | ------------- | ------------- |
| featured = true  | ★      | 노란색 (fill) | 대표 프로젝트 |
| featured = false | ☆      | 회색          | 일반 프로젝트 |

### 6.3 삭제 확인

포스트 삭제와 동일하게 AlertDialog로 확인합니다.

## 8. 카테고리 관리 (`/admin/categories`)

### 8.1 기능 개요

블로그 글에 사용되는 카테고리를 관리하는 페이지입니다.

```
┌──────────────────────────────────────────┐
│  카테고리 관리                            │
├──────────────────────────────────────────┤
│  [새 카테고리 입력창]     [+ 추가]        │
│  Enter 키로도 추가 가능                  │
├──────────────────────────────────────────┤
│  개발일지    [편집] [삭제]                │
│  알고리즘    [편집] [삭제]                │
│  언어/도구   [편집] [삭제]                │
│  개념정리    [편집] [삭제]                │
│  회고        [편집] [삭제]                │
└──────────────────────────────────────────┘
```

### 8.2 카테고리 추가

입력창에 이름을 입력하고 [+ 추가] 버튼 또는 Enter 키를 눌러 추가합니다.

### 8.3 인라인 편집

[편집] 버튼을 클릭하면 해당 행이 **수정 가능한 입력창으로 바뀝니다**.  
다른 페이지로 이동하지 않고 목록에서 바로 수정합니다.

```
"개발일지"  [편집] [삭제]
    │  [편집] 클릭
    ▼
[개발일지     ] [✓ 저장] [✕ 취소]
    │  이름 변경 후 ✓ 클릭
    ▼
"개발 로그"  [편집] [삭제]  ← 변경된 이름으로 업데이트
```

### 8.4 삭제 확인

카테고리 삭제도 AlertDialog로 확인 후 진행합니다.

## 10. 현재 상태 및 주의사항

### 10.1 인증 없음 (보안 주의)

현재 Admin 페이지는 **누구나 URL을 알면 접근 가능**합니다.  
Firebase Authentication을 추가하면 로그인한 관리자만 접근하도록 제한할 수 있습니다.

> 이 프로젝트는 현재 **학습/포트폴리오 목적**이므로 인증은 추후 과제입니다.

### 10.2 Mock 데이터 한계

현재는 실제 데이터베이스 없이 코드에 직접 작성된 Mock 데이터를 사용합니다.  
따라서 관리자에서 수정해도 **페이지 새로고침 시 원래 데이터로 돌아옵니다**.

### 10.3 Firebase 연결 방법 (개요)

실제 데이터 저장을 위해 Firebase Firestore를 연결할 때는,  
`src/lib/services/posts.ts`, `projects.ts`, `categories.ts` 파일의  
Mock 함수들을 Firestore SDK 호출로 교체합니다.

```typescript
// 현재 (Mock)
export async function getAllPosts(): Promise<Post[]> {
  return mockPosts;
}

// Firestore 연결 후
export async function getAllPosts(): Promise<Post[]> {
  const snapshot = await getDocs(collection(db, "posts"));
  return snapshot.docs.map((doc) => ({ id: doc.id, ...doc.data() }) as Post);
}
```
