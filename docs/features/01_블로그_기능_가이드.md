# 블로그 기능 가이드

> 이 문서는 ohdevlogfolio의 블로그 기능 전체를 설명합니다.  
> 코드를 처음 보는 분도 이해할 수 있도록 흐름과 구조를 자세히 설명합니다.

---

## 1. 블로그란 무엇인가요?

이 사이트의 블로그는 **개발자가 공부한 내용이나 프로젝트 경험을 글로 정리해서 공개하는 공간**입니다.  
글 목록 페이지, 글 상세 페이지, 검색·필터 기능, 이전/다음 글 이동까지 갖추고 있습니다.

---

## 2. 블로그 페이지 구조

```
/blog               → 공개된 블로그 글 목록 (검색 + 태그 필터 포함)
/blog/[slug]        → 개별 글 상세 페이지 (Markdown 본문 표시)
```

> **slug란?**  
> URL에 사용되는 글 고유 식별자입니다. 예를 들어 글 제목이  
> "Next.js App Router 완전 정복"이라면 slug는 `nextjs-app-router-guide` 처럼  
> 영문 소문자와 하이픈으로 구성합니다.

---

## 3. 전체 데이터 흐름

아래 흐름도는 사용자가 블로그 목록 페이지를 열었을 때 무슨 일이 일어나는지를 보여줍니다.

```
사용자 브라우저
    │
    │  /blog 접속
    ▼
app/blog/page.tsx  (Server Component — 서버에서 실행)
    │
    │  getPublishedPosts() 호출
    ▼
lib/services/posts.ts
    │
    │  현재: mockPosts 배열에서 published=true 필터링
    │  (Firebase 연결 후: Firestore에서 읽어옴)
    ▼
BlogFilter.tsx  (Client Component — 브라우저에서 실행)
    │
    ├── 검색어 상태 (useState)
    ├── 선택된 태그 상태 (useState)
    │
    │  posts.filter(...)로 화면에 표시할 글 결정
    ▼
PostCard.tsx × N개  → 화면에 카드 렌더링
```

> **Server Component vs Client Component 차이점**
>
> - **Server Component**: 빌드 시 또는 요청 시 서버(또는 빌드 머신)에서 실행됩니다.  
>   데이터를 미리 가져와서 HTML로 만들어 보내줍니다. 빠르고 SEO에 유리합니다.
> - **Client Component**: 사용자의 브라우저에서 실행됩니다.  
>   `useState`, `useEffect` 같은 상태 관리가 필요한 경우 사용합니다.  
>   파일 상단에 `"use client"` 선언이 있으면 클라이언트 컴포넌트입니다.

## 4. 블로그 목록 페이지 (`/blog`)

### 4.1 구성 파일

| 파일                                 | 역할                                          | 종류             |
| ------------------------------------ | --------------------------------------------- | ---------------- |
| `src/app/blog/page.tsx`              | 서버에서 글 데이터를 가져와 BlogFilter에 넘김 | Server Component |
| `src/components/blog/BlogFilter.tsx` | 검색·태그 필터 UI와 PostCard 렌더링           | Client Component |
| `src/components/blog/PostCard.tsx`   | 개별 글 카드 (썸네일, 제목, 요약, 태그, 날짜) | Client Component |

### 4.2 검색 기능

사용자가 검색창에 글자를 입력하면, **입력할 때마다 실시간으로** 목록이 필터링됩니다.  
서버 요청 없이 이미 받아온 데이터에서 걸러내기 때문에 빠르게 동작합니다.

```
검색창에 "React" 입력
    │
    ▼
posts.filter(post =>
  post.title.toLowerCase().includes("react") ||
  post.excerpt.toLowerCase().includes("react")
)
    │
    ▼
"React" 관련 글만 화면에 표시
```

**검색 범위:** 글 제목(title) + 요약(excerpt)

### 4.3 태그 필터 기능

글마다 태그가 붙어 있습니다. (예: `React`, `TypeScript`, `Next.js`)  
태그 버튼을 클릭하면 해당 태그가 있는 글만 보여줍니다.  
같은 태그를 다시 클릭하면 필터가 해제됩니다.

```
"React" 태그 클릭
    │
    ▼
selectedTag = "React"
    │
    ▼
posts.filter(post => post.tags.includes("React"))
    │
    ▼
React 태그가 있는 글만 표시

"React" 태그 다시 클릭
    │
    ▼
selectedTag = null  (필터 해제)
    │
    ▼
전체 글 표시
```

### 4.4 화면 레이아웃

```
┌─────────────────────────────────────────────┐
│  블로그                                       │
│  총 N개의 글                                  │
├─────────────────────────────────────────────┤
│  [검색창 🔍]  [React] [TypeScript] [Next.js] │
│                          ← 태그 필터 버튼     │
├─────────────────────────────────────────────┤
│  ┌─────────┐  ┌─────────┐  ┌─────────┐     │
│  │ PostCard│  │ PostCard│  │ PostCard│     │
│  └─────────┘  └─────────┘  └─────────┘     │
│  ┌─────────┐  ┌─────────┐  ...             │
└─────────────────────────────────────────────┘
```

## 5. 블로그 상세 페이지 (`/blog/[slug]`)

### 5.1 구성 파일

| 파일                                      | 역할                               |
| ----------------------------------------- | ---------------------------------- |
| `src/app/blog/[slug]/page.tsx`            | 글 상세 페이지 (서버 컴포넌트)     |
| `src/components/blog/MarkdownContent.tsx` | Markdown 본문을 HTML로 변환해 표시 |

### 5.2 정적 경로 생성 (Static Export)

이 프로젝트는 Firebase Hosting에 정적 파일로 배포됩니다.  
그래서 빌드할 때 모든 글의 URL을 미리 만들어 두어야 합니다.  
이를 위해 `generateStaticParams`를 사용합니다.

```typescript
// 빌드 시 실행되어 모든 slug 목록을 미리 생성
export async function generateStaticParams() {
  const posts = await getPublishedPosts();
  return posts.map((post) => ({ slug: post.slug }));
}
// 결과: /blog/nextjs-app-router-guide, /blog/typescript-tips, ... 등의 페이지가 미리 생성됨
```

> **왜 미리 만들어야 할까요?**  
> 일반 서버가 있다면 요청이 들어올 때마다 페이지를 만들 수 있습니다.  
> 하지만 Firebase Hosting은 정적 파일 서버라서 미리 만든 파일만 보낼 수 있습니다.  
> `generateStaticParams`는 "이런 URL들을 빌드 시에 미리 만들어 둬"라고 알려주는 역할입니다.

### 5.3 이전/다음 글 네비게이션

글 상세 페이지 하단에 이전 글과 다음 글로 이동하는 링크가 있습니다.

```
이전 글이 있을 때                 다음 글이 있을 때
┌───────────────────────────────────────────┐
│ ← [이전 글 제목]    [다음 글 제목] →     │
└───────────────────────────────────────────┘
```

**동작 원리:**

```
1. 모든 공개 글을 작성일(createdAt) 기준 오래된 순으로 정렬
2. 현재 글의 위치(index) 파악
3. index - 1 = 이전 글, index + 1 = 다음 글
4. 없으면 해당 방향 링크 숨김
```

### 5.4 SEO 메타데이터 자동 생성

각 글 페이지마다 브라우저 탭 제목과 검색 엔진용 설명이 자동으로 설정됩니다.

```typescript
export async function generateMetadata({ params }) {
  const post = await getPostBySlug(params.slug);
  return {
    title: post.title, // 브라우저 탭 제목
    description: post.excerpt, // 검색 엔진 미리보기 텍스트
  };
}
```

### 5.5 존재하지 않는 글 처리

URL을 직접 입력해서 없는 글에 접속하면 자동으로 404 페이지로 이동합니다.

```typescript
const post = await getPostBySlug(slug);
if (!post) notFound(); // Next.js의 404 처리 함수
```

## 7. 글 데이터 구조 (Post 타입)

```typescript
interface Post {
  id: string; // 고유 식별자 (예: "1", "abc-123")
  title: string; // 글 제목
  slug: string; // URL용 식별자 (예: "nextjs-app-router-guide")
  excerpt: string; // 요약 (목록에서 미리 보기로 표시)
  content: string; // 본문 (Markdown 형식)
  thumbnailUrl: string; // 썸네일 이미지 URL
  tags: string[]; // 태그 배열 (예: ["React", "TypeScript"])
  category?: string; // 카테고리 (선택 사항, 예: "개발일지")
  published: boolean; // true = 공개, false = 비공개
  createdAt: string; // 작성일 (ISO 8601 형식, 예: "2024-01-20T00:00:00.000Z")
  updatedAt: string; // 수정일
}
```

> **`?`가 붙은 필드(category?)는 선택 사항**입니다.  
> 값이 없어도 에러가 나지 않으며, 나중에 추가할 수 있습니다.

## 8. 유저 플로우 (User Flow)

사용자가 블로그를 어떻게 사용하는지 전체 흐름입니다.

```
[홈 페이지 방문]
        │
        │  "블로그" 메뉴 클릭 또는
        │  최근 글 섹션에서 "전체 보기" 클릭
        ▼
[/blog — 블로그 목록]
        │
    ┌───┴────────────────────────┐
    │                            │
    │  검색창에 키워드 입력       │  태그 버튼 클릭
    ▼                            ▼
[검색 결과 표시]          [태그 필터 결과 표시]
    │                            │
    └───────────┬────────────────┘
                │  글 카드 클릭
                ▼
    [/blog/[slug] — 글 상세]
                │
        ┌───────┴───────┐
        │               │
        ▼               ▼
  [이전 글로 이동]  [다음 글로 이동]
```

## 9. 현재 데이터 소스

현재는 실제 데이터베이스 대신 코드에 직접 작성된 **Mock 데이터**를 사용합니다.

| 파일                        | 내용                                                              |
| --------------------------- | ----------------------------------------------------------------- |
| `src/lib/mock/posts.ts`     | 테스트용 블로그 글 데이터 배열                                    |
| `src/lib/services/posts.ts` | 데이터를 읽고 쓰는 함수들 (현재 mock 사용, Firebase 연결 시 교체) |

> **Mock 데이터의 한계:**  
> Admin에서 글을 추가/수정/삭제해도 페이지를 새로고침하면 원래 데이터로 돌아옵니다.  
> Firebase Firestore를 연결하면 이 문제가 해결됩니다.
