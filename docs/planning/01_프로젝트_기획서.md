## 1. 프로젝트 개요

### 1.1 프로젝트명

**ohdevlogfolio**

### 1.2 한 줄 소개

취업 준비와 학습 과정을 기록하면서, 직접 구현한 프로젝트와 학습 내용을 한 곳에서 관리하고 공유하기 위한 개발자 포트폴리오 겸 학습 블로그입니다.

### 1.3 핵심 목표

| 목표            | 설명                                                                                                |
| --------------- | --------------------------------------------------------------------------------------------------- |
| 포트폴리오 구축 | 직접 개발한 프로젝트들을 시각적으로 정리하여 채용 담당자와 클라이언트에게 제공합니다.               |
| 학습 기록       | React, Next.js, Java, Spring Boot 등 다양한 기술을 공부하며 얻은 개념과 경험을 블로그로 기록합니다. |
| 기술 실증       | 이 사이트 자체가 Next.js + Firebase 조합의 실무 수준 구현 예시로 활용됩니다.                        |
| 콘텐츠 자기관리 | 관리자 대시보드에서 포스트와 프로젝트를 직접 CRUD하여 외부 CMS 없이 운영합니다.                     |

## 2. 추진 배경

### 2.1 개발 계기

취업 준비를 하면서 두 가지 필요성이 생겼습니다.

1. **포트폴리오 공간 필요** — GitHub 링크만으로는 프로젝트를 시각적으로 보여주기 어렵고, 기술 역량을 한눈에 전달하기 어렵습니다.
2. **학습 기록 정리 필요** — 알고리즘, 개발 일지, 사용한 언어/도구에 대한 생각을 체계적으로 정리할 공간이 필요했습니다.

단순히 개인 메모가 아니라 **채용 담당자, 프리랜서 클라이언트, 개발자 커뮤니티**가 모두 방문할 수 있는 공개 포트폴리오 사이트로 만들기로 했습니다.

### 2.2 기존 방식의 한계

| 기존 방식             | 한계                                                                |
| --------------------- | ------------------------------------------------------------------- |
| GitHub Profile README | 텍스트/뱃지 위주로, 실제 프로젝트 데모를 보여주기 어렵습니다.       |
| Notion 페이지 공유    | 개발 스택 시연이 어렵고, 커스터마이징이 제한적입니다.               |
| Tistory / Velog       | 외부 플랫폼 의존으로 디자인과 구조를 직접 설계할 수 없습니다.       |
| 단순 정적 HTML        | 관리자 기능 없이 파일을 직접 수정해야 하므로 유지보수가 불편합니다. |

### 2.3 이 프로젝트의 개선 방향

> 포트폴리오와 블로그를 **하나의 사이트**에서 운영하고, **관리자 대시보드**로 직접 CRUD하며,  
> Firebase Hosting에 **정적 배포**하여 서버 비용 없이 운영합니다.

## 3. 서비스 범위

### 3.1 MVP 포함 범위

| 영역                | 기능                                                               |
| ------------------- | ------------------------------------------------------------------ |
| 포트폴리오 (홈)     | Hero 섹션, 기술 스택, 대표 프로젝트 목록, 연락처                   |
| 프로젝트 페이지     | 전체 프로젝트 목록, 기술스택 필터, GitHub/배포 링크, featured 강조 |
| 블로그 목록         | 포스트 목록, 검색, 태그 필터                                       |
| 블로그 상세         | 본문(Markdown), 이전/다음 글, 태그 표시                            |
| Admin 대시보드      | 통계 요약 카드, 빠른 링크                                          |
| Admin 포스트 관리   | CRUD, 공개/비공개 토글, 삭제 확인                                  |
| Admin 프로젝트 관리 | CRUD, featured 토글, 삭제 확인                                     |
| 공통                | 다크/라이트 모드, 모바일 반응형                                    |

### 3.2 MVP 제외 범위 (2차 확장)

| 기능                       | 이유                                                       |
| -------------------------- | ---------------------------------------------------------- |
| Admin 인증 (Firebase Auth) | 개인 사용 위주지만 공개 배포 후 보안 강화 예정             |
| 블로그 댓글                | 외부 서비스(Giscus, Disqus) 연동 검토 예정                 |
| 이미지 업로드              | Firebase Storage 미사용 원칙. `thumbnailUrl` 문자열로 대체 |
| RSS 피드                   | 블로그 독자 확보 후 추가 예정                              |
| 검색 고도화                | 현재 클라이언트 필터. 추후 Algolia 등 검토                 |
| 페이지네이션               | 초기에는 전체 목록 로드. 데이터 증가 후 추가               |
| 조회수 카운터              | Firestore 트랜잭션 기반으로 추후 구현                      |

## 5. 제약 조건

| 제약                               | 내용                                       | 이유                                         |
| ---------------------------------- | ------------------------------------------ | -------------------------------------------- |
| 정적 배포 필수                     | `next.config.ts`에 `output: "export"` 설정 | Firebase Hosting은 서버리스 정적 배포만 지원 |
| Firestore client SDK만 사용        | API Routes, Server Actions 미사용          | 서버 환경 없음                               |
| Firebase Storage 미사용            | 이미지는 `thumbnailUrl` 문자열로 처리      | 복잡도 및 비용 절감                          |
| Cloud Functions 미사용             | 서버 측 로직 없음                          | 아키텍처 단순화                              |
| 이미지 Next.js Image 최적화 비활성 | `images: { unoptimized: true }`            | 정적 내보내기와 호환되지 않음                |
